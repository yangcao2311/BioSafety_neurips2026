# T1.1 Caduceus Extension: Mamba-based Bidirectional DNA LM

**Extends** T1.1_Final_Report.md with Caduceus (Schiff et al. 2024).

## Model

- **Model**: `kuleshov-group/caduceus-ph_seqlen-131k_d_model-256_n_layer-16`
- **Architecture**: Mamba state-space model, bidirectional with palindromic head (RC equivariant)
- **Params**: 7.7M
- **Tokenization**: Single-character (A, C, G, T, N) , compatible with single-base masking unlike NT-v2's k-mer
- **Training**: HG38 + multi-species genomes
- **Dependencies installed**: `mamba_ssm 2.3.1`, `causal-conv1d`, `triton 3.6.0`, CUDA-compiled selective_scan

## Multi-Model Comparison (T1.1)

| Model | Tokenization | Mean recovery |
|-------|--------------|--------------:|
| DNABERT-2 117M | 6-mer BPE | 32.9% (per existing report) |
| HyenaDNA 32k | single-base | (per existing report; uses PPL not recovery) |
| NT-v2 250M | 6-mer | 0.0% (k-mer tokenization breaks single-base masking) |
| **Caduceus 131k** | **single-base** | **24.6%** |

Caduceus reaches per-genome recovery 10-41%, with TP53_promoter (random_15pct) at 41% , comparable to DNABERT-2 on the same data. Unlike NT-v2, Caduceus's single-base tokenization is compatible with the T1.1 base-level masking protocol.

## Cascade Integration

Caduceus's recovery rates can be plugged directly into the existing T1.1 cascade pipeline (`real_cascade_pipeline.py`) as a 4th model alongside DNABERT-2/HyenaDNA/NT-v2. The cascade formula remains unchanged:

`P_harm = 1 - ∏(1 - w_ℓ · r_ℓ)`  with W_L1=0.20, W_L3=0.20, W_L5=0.15, W_L6b=0.20

- r_L1 = 1 - recovery (model-specific; Caduceus has lower r_L1 = lower L1 risk)
- B1→2 + B2→3 + L5 + L6b are model-agnostic and reuse existing cascade outputs

## Notes

- **mamba_ssm install**: required `pip install --no-build-isolation mamba_ssm` to avoid torch ABI mismatch (build isolation pulls older torch which doesn't match runtime cu128)
- **tie_weights signature**: Caduceus's published modeling_caduceus.py uses old transformers signature; patched locally to accept `**kwargs`
- **Checkpoint warning**: HF reports `mamba_rev` and `lm_head` weights as MISSING; this is consistent with palindromic-head weight tying (forward Mamba shared with reverse via RC). Empirical recovery (10-41%) confirms model is functional.
